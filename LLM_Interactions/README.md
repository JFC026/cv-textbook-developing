# 与LLM协作：如何获取高质量回答

## 一、为什么需要学习与LLM协作

在大模型时代，掌握与LLM高效协作的能力已成为一项核心技能。LLM作为人类知识的结晶，面对几乎所有问题时，都能迅速输出可行的答案。然而，有经验的使用者会发现，同一个问题问法不同，得到的输出就可能存在着天壤之别。本项目中，我们与百度文心大模型协作完成五个经典计算机视觉算法的纯Python实现，积累了宝贵的LLM协作经验。在这里，我们将分享使用LLM获取较高质量输出的心得，旨在帮助读者：
- **提升提问质量**，获取更精准、实用的回答
- **降低沟通成本**，减少无效交互轮次
- **培养批判性思维**，学会验证和评估LLM输出

---

## 二、高效提问的核心原则

### 2.1 四要素提问法
每次提问应尽可能包含以下四个要素：

- **Role（角色）**：明确LLM应扮演的角色
- **Instruction（指令）**：具体要做什么
- **Context（上下文）**：提供相关背景信息
- **Example（示例）**：给出输入输出的示例（尤其特定格式的输入输出）

**示例：**
```
【角色】你是一位资深的计算机视觉算法工程师和Python开发导师。
【上下文】我正在实现一个纯Python的KNN算法，不使用任何深度学习框架，只使用NumPy。
【指令】请帮我设计一个优化的距离计算函数，要求：
1. 避免使用显式循环，利用NumPy矩阵运算
2. 时间复杂度尽可能低
3. 支持批量计算
4. 注明每一步的含义
【示例】输入是两个矩阵X_train (N_train, D)和X_test (N_test, D)，输出是距离矩阵(N_test, N_train)
```

### 2.2 分步骤、渐进式提问
LLM面对涉及多个步骤的复杂问题时，容易出现忘记问题背景以及上下文等问题，从而在一轮又一轮的追问质疑中彻底搞砸。我们要做的是，**将复杂问题拆解为多个简单问题**，这则需要读者真正的理解问题而有自己的思维框架。

**不推荐的提问方式：**
```
如何实现一个完整的KNN分类器？给出完整代码
```

**推荐的渐进式提问：**
```
第一步：请帮我设计KNN类的初始化方法，需要存储训练数据和标签
第二步：请设计欧氏距离的矩阵计算方法，不使用循环
第三步：如何实现K个最近邻的查找和投票机制？
第四步：如何添加交叉验证选择最优K值的功能？
```
这种拆分问题的方式，不仅使得LLM可以更专注于当前的任务从而输出质量更高的回答，而且在调试时更容易定位问题（是否出现在当前步骤）。

### 2.3 明确具体约束条件
限制条件越明确，也就是给LLM的信息越精准，越能显著提高回答质量：

**差示例：**
```
怎么写Softmax函数？
```

**好示例：**
```
请用纯Python实现Softmax函数，要求：
1. 考虑数值稳定性（防止指数溢出）
2. 输入是一个二维数组，每行是一个样本的logits
3. 输出是相同形状的概率矩阵，每行和为1
4. 使用NumPy但不能用scipy.special.softmax
5. 提供数学公式说明和代码注释
```

```
模板1：概念解释
【角色】你是一位[领域]专家教师
【指令】请向有一定编程基础但刚接触[概念]的学生解释[概念]
【要求】1. 用比喻或生活例子说明 2. 给出数学定义 3. 提供简单代码示例

模板2：数学推导
【角色】你是一位数学导师
【指令】请逐步推导[公式/算法]的数学过程
【要求】1. 从基本定义开始 2. 每步标注使用的定理或规则 3. 给出最终公式
```

## 五、批判性评估与验证方法

“尽信书不如无书”，这句话大家都听过，在与LLM的互动中也是如此。LLM绝不是掌握一切知识的绝对正确学者，相反，由于“AI幻觉”等内在局限性，它的回答常常会带有虚假、顺从用户的成分。在我们之前的LLM使用经验中，甚至出现过LLM被摆证据明确指出错误后依然“死鸭子嘴硬”，不肯认错改正的情况。为了防止被LLM“欺骗”，我们必须擦亮眼睛，用批判性思维去审查LLM的输出以保证其真实性。

### 5.1 LLM输出的常见问题
- **代码幻觉**：生成看似合理但无法运行的代码，包括不限于在长代码中编造上文根本没有的变量、函数等  
- **过时信息**：推荐已弃用的API或方法，这通常是因为LLM的知识库没有更新新版本库的用法改动，或者LLM调用的库版本与我们其他库版本不兼容而发生冲突等  
- **安全漏洞**：忽略约束条件或安全考虑

### 5.2 三步验证法
**第一步：常识检查**
- 代码是否能直接运行？
- 数学推导是否符合基本原理？
- 算法复杂度是否合理？

**第二步：交叉验证**
- 用不同方式提问，或者去找其他AI提问，比较答案一致性
- 要求LLM提供信息出处，查阅官方文档验证API使用
- 在小规模数据上测试代码，增加print等调试信息

**第三步：详细审查**
- 逐行理解代码逻辑
- 检查是否符合项目规范
- 确认满足所有需求

## 七、总结：LLM协作的最佳实践流程

### 7.1 准备阶段
- **明确目标**：清楚知道要解决什么问题并建立基本思路
- **整理上下文**：准备相关代码、报错信息、背景资料
- **选择合适角色**：根据问题选择专家角色

### 7.2 提问阶段
- **使用结构化提示**：遵循四要素
- **提供示例**：输入输出示例能大幅提高质量
- **分步骤提问**：复杂问题拆解为简单问题链或分步骤
- **明确约束**：技术栈、性能要求、规范限制等

### 7.3 评估阶段
- **保持批判态度**：默认LLM可能出错
- **多轮迭代**：基于回答进一步追问细节，并要求对不确定信息提供官方出处（然而LLM在多轮对话中易发生忘记之前回答细节的情形，因此提问需有效率）
- **实际测试**：代码一定要运行测试
- **记录学习**：记录成功和失败的交互模式，分析哪里可能导致LLM产生了误解

### 7.4 长期协作
-  **建立个人知识库**：积累高质量的提示词模板
- **分析交互模式**：总结哪些类型的提问获得更好回答
- **持续学习**：LLM能力在进化，协作方式也需要不断更新

---

## 八、结语

通过本项目的实践，我们深刻体会到：**LLM不是替代人类思考的工具，而是放大人类智能的杠杆**。善于提问的人能从LLM获得巨大价值，而不善提问的人可能得到无用甚至误导的信息。

掌握与LLM协作的艺术，本质上是学习如何清晰表达问题、如何系统化思考、如何批判性评估信息。这些能力不仅在AI时代至关重要，也是终身学习者的核心素养。

我们撰写这份协作经验文档，希望帮助更多人成为高效的人机协作者，共同推动AI技术的负责任和创造性应用。
